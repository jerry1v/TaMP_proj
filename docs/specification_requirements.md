# Спецификация требований

## 1. Назначение системы

Система предназначена для выполнения следующих функций:

- регистрация пользователей;
- авторизация пользователей;
- шифрование данных алгоритмом AES;
- получение хеша SHA1;
- вычисление квадратного корня методом Ньютона;
- внедрение сообщения в музыкальный файл;
- взаимодействие клиента и сервера по сети.

---

## 2. Функциональные требования

### FR-01 Регистрация

Система должна обеспечивать регистрацию пользователя по логину и паролю.

### FR-02 Авторизация

Система должна обеспечивать авторизацию пользователя по логину и паролю.

### FR-03 AES

Система должна выполнять шифрование переданных данных.

### FR-04 SHA1

Система должна вычислять хеш переданных данных.

### FR-05 Метод Ньютона

Система должна вычислять квадратный корень числа методом Ньютона.

### FR-06 Стеганография

Система должна обеспечивать внедрение сообщения в музыкальный файл.

### FR-07 Работа по сети

Клиент должен иметь возможность отправлять запросы серверу и получать ответы.

### FR-08 Многопользовательская работа

Сервер должен поддерживать подключение нескольких клиентов одновременно.

---

## 3. Нефункциональные требования

### NFR-01 Производительность

Время обработки запроса не должно превышать 5 секунд.

### NFR-02 Надёжность

Сервер должен продолжать работу при отключении клиента.

### NFR-03 Удобство использования

Клиентское приложение должно иметь графический интерфейс.

### NFR-04 Совместимость

Программное обеспечение должно работать под операционной системой Windows.

### NFR-05 Документирование

Исходный код должен содержать комментарии Doxygen.

---

## 4. Ограничения

- Язык программирования: C++
- Сетевое взаимодействие: TCP/IP
- Клиентский интерфейс: Qt
- База данных: Singleton-хранилище в памяти

---

## 5. Роли пользователей

### Пользователь

Может:
- зарегистрироваться;
- войти в систему;
- использовать функции AES;
- использовать функции SHA1;
- использовать метод Ньютона;
- использовать стеганографию.

### Администратор

Может:
- просматривать список пользователей;
- управлять пользователями;
- получать информацию о работе системы.

---

## 6. Требования к безопасности

- доступ к системе осуществляется после авторизации;
- пароль пользователя хранится отдельно от логики клиента;
- обмен данными осуществляется через сервер.
